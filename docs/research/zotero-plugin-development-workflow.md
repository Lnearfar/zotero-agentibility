# Zotero plugin development workflow

**Research date:** 2026-09-08. Research only; no Zotero profile, UI, or code was changed.

## Verified mechanics

- These are **community projects**, not Zotero-maintained templates: `zotero-plugin-template` and `zotero-plugin-toolkit` are windingwind projects; `zotero-plugin-scaffold` is the extracted build/server project maintained under `zotero-plugin-dev` ([template README](https://github.com/windingwind/zotero-plugin-template/blob/306d4e2a0959a7b2f5e44bb38169fb25f841dbaf/README.md), [scaffold README](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/README.md)).
- Template commands are `npm install`, `npm start` (`zotero-plugin serve`), `npm run build` (`zotero-plugin build && tsc --noEmit`), and `npm test` (`zotero-plugin test`) ([package.json](https://github.com/windingwind/zotero-plugin-template/blob/306d4e2a0959a7b2f5e44bb38169fb25f841dbaf/package.json)). The CLI also exposes `serve`/`dev`, `build`, `test`, and `release`; there is no separate install command. `serve` prebuilds, launches Zotero, watches configured sources with a 500-ms debounce, rebuilds, and reloads; it does not restart the application ([Serve](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/src/core/server.ts), [watcher](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/src/utils/watcher.ts)).
- Default development mode needs **no first manual XPI install**. The runner starts Zotero with `--purgecaches`, `no-remote`, the selected profile/data directory, `--jsdebugger`, and a loopback debugger port, then sends `installTemporaryAddon` for the built `dist/addon` directory over Firefox RDP; changes send the add-on actor’s `reload` request ([runner](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/src/utils/zotero-runner.ts), [RDP client](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/src/utils/zotero/remote-zotero.ts)). `server.asProxy=true` is the legacy proxy-file path; the docs say it does not support reload, and its source directly edits `extensions.json`; do not use it.
- Prerequisites are Node `>=22.8.0` for current Scaffold, Git, and (per the template) a Zotero beta. Create a beta/development profile with `/path/to/zotero -p`; set `ZOTERO_PLUGIN_ZOTERO_BIN_PATH` (required), and preferably explicit `ZOTERO_PLUGIN_PROFILE_PATH` plus `ZOTERO_PLUGIN_DATA_DIR` in an uncommitted `.env` ([template env](https://github.com/windingwind/zotero-plugin-template/blob/306d4e2a0959a7b2f5e44bb38169fb25f841dbaf/.env.example), [serve docs](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/docs/src/serve.md#zotero-and-profile-path), [Scaffold package](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/package.json)). Sources/dist and serve flags (`asProxy`, `devtools`, `startArgs`, `prebuild`) belong in `zotero-plugin.config.ts`; machine paths/kill command use environment variables. `.env` currently does not override existing system variables.

## Compatibility, tests, and risks

The scaffold docs claim RDP reload for Zotero 7+, while the template advertises Zotero 7 and toolkit 5.1+ explicitly says Zotero 8; none claims Zotero 10. Official Zotero 10 docs confirm the Firefox 140 base and compatibility guidance, not Scaffold’s RDP integration ([Zotero 10](https://www.zotero.org/support/dev/zotero_10_for_developers)). Linux is implemented, but built-in headless testing is documented only for Ubuntu 22.04/24.04. Treat Linux/Zotero 10 as an isolated-profile acceptance target, not verified compatibility. `zotero-plugin test` is native live-Zotero Mocha/Chai testing with temporary profile/data, watch mode, and optional Linux headless operation ([test docs](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/docs/src/test.md)); this repository has no scaffold test harness yet.

## Minimal plan for this repository

Use scaffold only as a dev dependency/configured copier: preserve [`check.sh`](../../zotero-extension/check.sh), [`manifest.json`](../../zotero-extension/manifest.json) (ID `zotero-agentibility@local`, 7.0–10.*), [`bootstrap.js`](../../zotero-extension/bootstrap.js), [`runtime.js`](../../zotero-extension/runtime.js), and the checked-in locale/license assets; copy those static files into scaffold’s `.scaffold/build/addon`, disable generated-manifest rewriting, and keep the existing XPI/release path. Do **not** add toolkit unless bridge code later needs its APIs: toolkit is an API library, not the hot-reload server ([toolkit README](https://github.com/windingwind/zotero-plugin-toolkit/blob/ec6353cdb7901aee2358e5f87167284f181e1441/README.md)). RDP reload will invoke this add-on’s `shutdown()`/`startup()`; current `shutdown()` calls asynchronous `AgentibilityRuntime.stop()` without awaiting it, so acceptance must confirm the worker, notifier, Item-pane section, and HTTP hooks do not overlap across reloads ([local lifecycle](../../zotero-extension/bootstrap.js), [runtime](../../zotero-extension/runtime.js)). Never point the runner at the production profile: it rewrites `prefs.js`, uses `no-remote`, and Linux exit can `pkill -9 zotero`. The template lockfile currently pins Scaffold 0.8.2 while its current main is 0.9.2, so pin/review the chosen version ([template lockfile](https://github.com/windingwind/zotero-plugin-template/blob/306d4e2a0959a7b2f5e44bb38169fb25f841dbaf/package-lock.json), [Scaffold package](https://github.com/zotero-plugin-dev/zotero-plugin-scaffold/blob/54b93b38d4ba2bfccc79efe8f29525388ddb0dab/package.json)). Unknowns requiring acceptance are actual Zotero 10 RDP reload behavior, clean worker restart timing, and compatibility of the current release build on this Linux installation.
