# Extension bridge protocol

Version 1 uses one loopback endpoint:

```text
POST /zotero-agent-library/v1/operation
Authorization: Bearer <token>
Content-Type: application/json
```

The token is generated by the manually installed Extension at first startup and stored at `~/.config/zotero-agent-library/bridge-token` with mode `0600`. It is never bundled in the XPI or logged.

Zotero 9 rejects extension manifests without `applications.zotero.update_url`. Until this repository has a release host, the manifest uses an inert HTTPS loopback URL on `127.0.0.1:1`; it cannot send update requests outside the machine and normal installation remains manual.

Requests use a fixed-operation envelope:

```json
{"protocol":1,"operation":"health","arguments":{}}
```

The first runnable slice allows only `health`; it returns the protocol and Extension release version. Missing or invalid authentication, malformed or oversized JSON, protocol mismatch, and unknown operations fail without evaluation. The bridge never accepts JavaScript source. Later write operations must be individually allowlisted, validate My Library and current Zotero state, and use Zotero transactions.
